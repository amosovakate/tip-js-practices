## Задание 3. Сводка выполнения задач

(N = 1 в журнале)

Программа `practice-01/js/progress.js` получает общее число задач `totalTasks`
и число выполненных `completedTasks`, проверяет их и выводит сводку.

### Как работает программа

1. Сначала проверяются входные данные. При первой найденной ошибке выводится одно
   сообщение, начинающееся с «Ошибка:», обычная сводка не выводится.
   Проверки идут по порядку: строка, нечисловое значение (`NaN`, `Infinity`),
   дробное число, отрицательное число, значение больше 1000, выполнено больше,
   чем существует.
2. Строка проверяется раньше остальных, потому что `Number.isFinite("5")`
   возвращает `false`, и без этого строка получила бы неверное сообщение.
3. Если обе величины равны 0, выводится «Задач пока нет». Процент при этом не
   считается, поэтому деления на ноль нет.
4. Для остальных данных считаются остаток (`totalTasks - completedTasks`) и
   процент (`completedTasks / totalTasks * 100`, один знак после точки через
   `toFixed(1)`). Статус определяется по исходным количествам, а не по
   округлённому проценту. Ничего не захардкожено, всё вычисляется.

## Задание 4. План выполнения оставшихся задач

(N = 1 в журнале)

Программа `practice-01/js/plan.js` получает общее число задач `totalTasks`,
число выполненных `completedTasks` и дневную норму `dailyLimit`, проверяет их
и определяет, за сколько дней будут выполнены оставшиеся задачи.

### Как работает программа

1. Сначала проверяются входные данные. При первой найденной ошибке выводится одно
   сообщение, начинающееся с «Ошибка:», цикл не запускается. Проверки идут по
   порядку: строка, нечисловое значение (`NaN`, `Infinity`), дробное число,
   отрицательное число, значение больше 1000, выполнено больше, чем существует.
2. После этого проверяется `dailyLimit`. Дневная норма должна быть целым числом
   от 1 до 1000. Проверка выполняется даже при отсутствии оставшихся задач.
3. Если `totalTasks` равно `completedTasks`, оставшихся задач нет. Выводится
   «Потребуется дней: 0», цикл не выполняется.
4. Для остальных допустимых данных вычисляется количество оставшихся задач:
   `totalTasks - completedTasks`.
5. Для расчёта плана используется цикл `while`. На каждой итерации увеличивается
   номер дня, определяется количество задач на этот день и уменьшается остаток.
6. Количество задач на текущий день определяется с помощью `Math.min()`. Поэтому
   в последний день выполняется только оставшееся количество задач, если оно
   меньше дневной нормы.
7. Цикл продолжается до тех пор, пока количество оставшихся задач не станет
   равно 0. После завершения цикла выводится количество потребовавшихся дней.

Программа корректно обрабатывает допустимые и недопустимые данные и определяет
количество дней, необходимое для выполнения оставшихся задач. Цикл `while`

а в последний день выполняется только оставшееся количество задач. При
недопустимых данных цикл не запускается.

## Дополнительное задание, вариант Б. План с выходными днями

Файл: `practice-01/js/plan-week.js`. Запуск: `node practice-01/js/plan-week.js`.
Решения заданий 3 и 4 не изменялись, расширение находится в отдельном файле.

### Как работает программа

- Первый календарный день это понедельник, суббота и воскресенье выходные.
  День недели вычисляется как `(номер дня - 1) % 7`: значения 0-4 это
  понедельник-пятница, 5 и 6 это суббота и воскресенье.
- Цикл `while` идёт по календарным дням, пока остаются невыполненные задачи.
  В рабочий день выполняется `Math.min(remaining, dailyLimit)` задач: не больше
  дневной нормы и не больше, чем осталось. В выходной задачи не выполняются,
  остаток не меняется.
- Выходные после последней задачи не добавляются: цикл заканчивается сразу,
  когда `remaining` становится равным 0, а это всегда происходит в рабочий день.
- Программа считает отдельно рабочие дни с выполнением задач (`workingDays`) и
  общее число календарных дней (`day - 1`, так как `day` увеличивается
  в конце каждого круга).
- Если оставшихся задач нет, цикл не запускается, оба счётчика равны нулю.
- Входные данные проверяются так же, как в задании 3 (строка, `NaN`, дробное,
  отрицательное, превышение 1000, выполнено больше, чем всего). Дневная норма
  `dailyLimit` должна быть целым числом от 1 до 1000. Проверка сделана как
  `dailyLimit < 1`, а не `=== 0`: при нуле или отрицательной норме задач не
  становилось бы меньше, и цикл был бы бесконечным.

### Контрольный случай

Данные `totalTasks = 6`, `completedTasks = 0`, `dailyLimit = 1`:

    День 1 (понедельник): выполнено 1, осталось 5
    День 2 (вторник): выполнено 1, осталось 4
    День 3 (среда): выполнено 1, осталось 3
    День 4 (четверг): выполнено 1, осталось 2
    День 5 (пятница): выполнено 1, осталось 1
    День 6 (суббота): выходной
    День 7 (воскресенье): выходной
    День 8 (понедельник): выполнено 1, осталось 0
    Рабочих дней с выполнением задач: 6
    Всего календарных дней: 8

Результат совпал с ожидаемым: 6 рабочих и 8 календарных дней.

### Собственные проверки

Формат данных: `totalTasks`, `completedTasks`, `dailyLimit`.

- **20, 0, 4:** 5 рабочих, 5 календарных дней. Последняя задача выполнена
  в пятницу, выходные не добавлены.
- **21, 0, 4:** 6 рабочих, 8 календарных дней. Одна задача переходит на
  понедельник следующей недели через два выходных дня.
- **5, 5, 3:** 0 рабочих, 0 календарных дней. Оставшихся задач нет,
  цикл не запускается.
- **3, 0, 5:** 1 рабочий, 1 календарный день. Дневная норма больше остатка,
  выполнено 3 задачи, а не 5.
- **12, 5, 3 (данные варианта 1):** 3 рабочих, 3 календарных дня.
- **5, 0, -1:** `Ошибка: дневная норма должна быть не меньше 1.`
  Программа не зависает.

### Вывод

Программа строит расписание по календарным дням с учётом выходных, отдельно
считает рабочие и календарные дни и корректно обрабатывает граничные случаи:
отсутствие задач, лимит больше остатка, недопустимую дневную норму.
