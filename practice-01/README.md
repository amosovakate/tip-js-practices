## Задание 2. Исследование типов и преобразований

### 1. `"8" + 2`
- Ожидание до запуска: `"82"`
- Фактическое значение: `82`
- Тип результата: string
- Объяснение: если один из операндов строка, оператор `+` выполняет конкатенацию. Число 2 превращается в строку `"2"` и присоединяется к `"8"`.

### 2. `"8" - 2`
- Ожидание до запуска: `6`
- Фактическое значение: `6`
- Тип результата: number
- Объяснение: оператор `-` работает только с числами, поэтому строка `"8"` преобразуется в число 8.

### 3. `Number("8") + 2`
- Ожидание до запуска: `10`
- Фактическое значение: `10`
- Тип результата: number
- Объяснение: строка явно преобразована в число, затем выполнено обычное сложение.

### 4. `"12" > "3"`
- Ожидание до запуска: `false`
- Фактическое значение: `false`
- Тип результата: boolean
- Объяснение: две строки сравниваются посимвольно, а не как числа. Первый символ `"1"` меньше `"3"`, поэтому `"12"` меньше `"3"`.

### 5. `12 === "12"`
- Ожидание до запуска: `false`
- Фактическое значение: `false`
- Тип результата: boolean
- Объяснение: строгое равенство не приводит типы. Число и строка это разные типы, поэтому значения не равны.

### 6. `Number("")`
- Ожидание до запуска: `0`
- Фактическое значение: `0`
- Тип результата: number
- Объяснение: пустая строка при преобразовании в число даёт 0.

### 7. `Number("text")`
- Ожидание до запуска: `NaN`
- Фактическое значение: `NaN`
- Тип результата: number
- Объяснение: текст нельзя преобразовать в число, поэтому получается `NaN` («не число»). Сам `NaN` имеет тип number.

### 8. `Boolean("false")`
- Ожидание до запуска: `true`
- Фактическое значение: `true`
- Тип результата: boolean
- Объяснение: любая непустая строка приводится к `true`, независимо от содержимого. Ложной является только пустая строка `""`.

### 9. `typeof null`
- Ожидание до запуска: `"object"`
- Фактическое значение: `"object"`
- Тип результата: string
- Объяснение: это историческая особенность JavaScript. `typeof null` возвращает `"object"`, хотя `null` является примитивом. Оператор `typeof` всегда возвращает строку.

### 10. `typeof NaN`
- Ожидание до запуска: `"number"`
- Фактическое значение: `"number"`
- Тип результата: string
- Объяснение: `NaN` относится к типу number. Результат `typeof` это строка.

## Задание 3. Сводка выполнения задач

Программа `practice-01/js/progress.js` получает общее число задач `totalTasks`
и число выполненных `completedTasks`, проверяет их и выводит сводку.

### Как работает программа

1. Сначала проверяются входные данные. При первой найденной ошибке выводится одно
   сообщение, начинающееся с «Ошибка:», обычная сводка не выводится.
   Проверки идут по порядку: строка, нечисловое значение (`NaN`, `Infinity`),
   дробное число, отрицательное число, значение больше 1000, выполнено больше,
   чем существует.
2. Строка проверяется раньше остальных, потому что `Number.isFinite("5")`
   возвращает `false`, и без этого строка получила бы неверное сообщение.
3. Если обе величины равны 0, выводится «Задач пока нет». Процент при этом не
   считается, поэтому деления на ноль нет.
4. Для остальных данных считаются остаток (`totalTasks - completedTasks`) и
   процент (`completedTasks / totalTasks * 100`, один знак после точки через
   `toFixed(1)`). Статус определяется по исходным количествам, а не по
   округлённому проценту. Ничего не захардкожено, всё вычисляется.

### Результаты проверок

- 12 и 5:осталось 7, прогресс 41.7%, статус «В работе». Совпало с ожидаемым.
- 0 и 0: «Задач пока нет», процент не рассчитывается. Совпало.
- 5 и 0: осталось 5, прогресс 0.0%, статус «Не начато». Совпало.
- 5 и 5: осталось 0, прогресс 100.0%, статус «Завершено». Совпало.
- 5 и 6: «Ошибка: выполнено больше, чем существует.» Совпало.
- -1 и 0: «Ошибка: отрицательное количество.» Совпало.
- 5 и 2.5: «Ошибка: дробное количество.» Совпало.
- "5" и 2: «Ошибка: вместо числа передана строка.» Совпало.
- 1001 и 0: «Ошибка: превышена верхняя граница.» Совпало.
- NaN и 0: «Ошибка: недопустимое числовое значение.» Совпало.

После проверок в файле возвращены данные варианта: `totalTasks = 12`, `completedTasks = 5`.

### Вывод

Программа корректно обрабатывает допустимые и недопустимые данные, не делит на
ноль и выводит сводку в требуемом формате.

## Задание 4. План выполнения оставшихся задач

Программа `practice-01/js/plan.js` получает общее число задач `totalTasks`,
число выполненных `completedTasks` и дневную норму `dailyLimit`, проверяет их
и определяет, за сколько дней будут выполнены оставшиеся задачи.

### Как работает программа

1. Сначала проверяются входные данные. При первой найденной ошибке выводится одно
   сообщение, начинающееся с «Ошибка:», цикл не запускается. Проверки идут по
   порядку: строка, нечисловое значение (`NaN`, `Infinity`), дробное число,
   отрицательное число, значение больше 1000, выполнено больше, чем существует.
2. После этого проверяется `dailyLimit`. Дневная норма должна быть целым числом
   от 1 до 1000. Проверка выполняется даже при отсутствии оставшихся задач.
3. Если `totalTasks` равно `completedTasks`, оставшихся задач нет. Выводится
   «Потребуется дней: 0», цикл не выполняется.
4. Для остальных допустимых данных вычисляется количество оставшихся задач:
   `totalTasks - completedTasks`.
5. Для расчёта плана используется цикл `while`. На каждой итерации увеличивается
   номер дня, определяется количество задач на этот день и уменьшается остаток.
6. Количество задач на текущий день определяется с помощью `Math.min()`. Поэтому
   в последний день выполняется только оставшееся количество задач, если оно
   меньше дневной нормы.
7. Цикл продолжается до тех пор, пока количество оставшихся задач не станет
   равно 0. После завершения цикла выводится количество потребовавшихся дней.

### Результаты проверок

* 12 и 5, дневная норма 3: осталось 7, прогресс выполнения: день 1 — выполнено 3, осталось 4; день 2 — выполнено 3, осталось 1; день 3 — выполнено 1, осталось 0. Потребовалось 3 дня. Совпало с ожидаемым.
* 10 и 4, дневная норма 3: осталось 6, день 1 — выполнено 3, осталось 3; день 2 — выполнено 3, осталось 0. Потребовалось 2 дня. Совпало.
* 5 и 3, дневная норма 10: осталось 2, за один день выполнено только 2 оставшиеся задачи. Потребовался 1 день. Совпало.
* 5 и 5, дневная норма 2: все задачи выполнены, выведено «Потребуется дней: 0», цикл не выполняется. Совпало.
* 0 и 0, дневная норма 2: задач не осталось, выведено «Потребуется дней: 0», цикл не выполняется. Совпало.
* 5 и 2, дневная норма 0: «Ошибка; цикл не запускается.» Совпало.
* 5 и 2, дневная норма 1.5: «Ошибка: дробной дневной нормы быть не должно.» Совпало.
* 5 и 6, дневная норма 2: «Ошибка: некорректное число выполненных задач.» Совпало.
* 5 и 2, дневная норма `"2"`: «Ошибка: дневная норма задана строкой.» Совпало.
* 5 и 2, дневная норма 1001: «Ошибка: превышена верхняя граница нормы.» Совпало.

После проверок в файле возвращены данные варианта: `totalTasks = 12`,
`completedTasks = 5`, `dailyLimit = 3`.

### Вывод

Программа корректно обрабатывает допустимые и недопустимые данные и определяет
количество дней, необходимое для выполнения оставшихся задач. Цикл `while`
пошагово формирует план выполнения, при этом остаток не становится отрицательным,
а в последний день выполняется только оставшееся количество задач. При
недопустимых данных цикл не запускается.
