| № | Прогноз до запуска | Фактический результат | Причина |

| 2 | `2` | `undefined` | В теле стрелочной функции с `{}` нет `return`: выражение `value * value` вычисляется, но результат не возвращается. |

**Исправление эксперимента 2.** Исходная причина: в теле стрелочной функции в фигурных скобках отсутствовал `return`.

```javascript
// до исправления
const square = (value) => {
  value * value;
};
console.log(square(4)); // undefined

// после исправления
const square = (value) => {
  return value * value;
};
console.log(square(4)); // 16 (number)
```

Результаты: до исправления — `undefined`, после — `16` (число).

## 4. Модель данных и функции

**Модель задачи:** объект с четырьмя полями.

| Поле | Правило |
|------|---------|
| `id` | положительное безопасное целое (`Number.isSafeInteger(id)` и `id > 0`), уникально в списке |
| `title` | строка; после `trim()` длина от 1 до 100; сохраняется очищенная строка |
| `completed` | логическое значение; при создании всегда `false` |
| `priority` | строго `"low"`, `"medium"` или `"high"`; по умолчанию `"medium"` |

**Файлы:** `src/data.js` — данные (`demoTasks`, `variantNumber`, `variantTasks`); `src/task-service.js` — девять функций без вывода и без глобального списка; `src/main.js` — демонстрационный сценарий и вывод; `checks.js` — готовые проверки; `my-checks.js` — собственные проверки.

**Результаты операций:**

| Функция | При успехе | При ошибке |
|---------|-----------|------------|
| `createTask` | `{ ok: true, task }` | `{ ok: false, error }` |
| `addTask`, `setTaskCompleted`, `renameTask`, `removeTask` | `{ ok: true, tasks }` (новый массив) | `{ ok: false, error }`; исходные данные не меняются |
| `findTaskById` | найденный объект | `undefined` |
| `getPendingTasks`, `getTaskTitles` | новый массив (в том числе пустой) | — |
| `getTaskStats` | `{ total, completed, pending, progress }` | — |

**Почему id не равен индексу.** `id` идентифицирует запись и не меняется после удаления соседних задач, а индекс — это текущее место в массиве. Например, задача с `id = 4` лежит на индексе 1. Поэтому поиск выполняется через `find`, а не через `tasks[id]`.

**Почему `getTaskStats` возвращает число, а не строку с процентом.** Число можно использовать в дальнейших расчётах и сравнениях без преобразования. `toFixed()` возвращает строку, поэтому он применяется только при отображении в `main.js` (например, `progress.toFixed(1)`), а не внутри расчёта.

**Какие объекты копируются при изменении задачи.** Создаётся новый массив (через `map`, `filter` или spread) и новый объект только для изменяемой задачи (`{ ...task, completed }`). Остальные задачи переиспользуются по ссылке и не изменяются. Копия поверхностная, что допустимо, потому что все поля задачи — примитивы.

## 9. Вывод

По сравнению с ПР1, где расчёты выполнялись над отдельными переменными, в этой работе задача представлена объектом, список задач — массивом, а операции над ним вынесены в функции и ES-модули. Возвращаемые значения используются везде: функции только возвращают результат (`{ ok, task }`, `{ ok, tasks }`, массивы, сводку), а вывод выполняет `main.js`. Ожидаемые ошибки возвращаются как данные `{ ok: false, error }` и не прерывают программу.

Неизменность данных обеспечена тем, что добавление выполняется через spread массива, обновление — через `map` и spread объекта, удаление — через `filter`; `push`, `splice` и прямые присваивания входным объектам не используются. Проверено сравнением `demoTasks` и `variantTasks` с исходными значениями после всех операций.

Ошибки, которые пришлось исправить: в эксперименте 2 пропущенный `return` (функция возвращала `undefined`); в `createTask` изначально неверно строились условия проверок (нужно `||` для `id`, но `&&` для списка допустимых приоритетов); папка `src` была названа `scr`, из-за чего Node не находил модуль.
